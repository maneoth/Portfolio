DevOps

The GitLab pipeline I set up for you

A typical delivery pipeline, adapted to your stack. Every stage runs automatically on each merge request, and nothing reaches production without passing the gates.

  1. buildDocker image built and pushed to the GitLab registry
  2. testUnit and integration tests, with coverage reported in the merge request
  3. qualitySonarQube quality gate blocks the merge on new issues
  4. securityTrivy or Aqua image scan, results tracked in DefectDojo
  5. infraTerraform plan on every MR, apply after approval
  6. deploy:stagingHelm release to a staging environment on Kubernetes
  7. approveManual approval with a protected environment
  8. deploy:prodSame Helm chart to production, with quick rollback

Reusable by every team

Shared CI templates with include and extends, so new projects get the full pipeline in a few lines.

On-premises to cloud migration

Migrating a client-installed product to a cloud platform on Azure

DTXCore was installed separately at every client site. The goal was one secure, centrally run platform on Azure that the vendor operates for all clients.

  • Designed and provisioned the Azure environment: AKS, VNet, ACR, Key Vault and Azure Monitor action groups.
  • Containerised the application components and made them run reliably on AKS.
  • Ran the database on AKS with a Kubernetes operator and pulled secrets from Key Vault through an operator.
  • Set up Keycloak for authentication, single sign-on and role-based access.
  • Enforced mutual TLS between services with a service mesh, and TLS on all external traffic.
  • Automated infrastructure setup and installation with Azure Pipelines; monitoring with Prometheus and Grafana.
